## changes
- `engine/src/bin/kvasir.rs`: `kvasir generate --model <dir> --prompt <text> --max-tokens N --seed S
  [--temperature T --top-p P] [--ignore-eos] [--prefill-chunk C] [--device D] [--json]` (clap derive).
  Checks the model dir, `config.json` and `tokenizer.json` up front with clear errors; `main` prints `error: ...` and
  exits 1. Encodes with the tokenizer post-processor and prepends BOS only if it is not already first. EOS ids =
  union of `config.json` and `generation_config.json` `eos_token_id` (number or list; tokenizer names as fallback).
  `Llama` is built with `max_seq = min(prompt + max_tokens - 1, max_position_embeddings, max_seq_limit)`,
  `max_tokens = min(prefill_chunk, prompt)`, `max_head_rows = 1`. Prompt chunks use `Logits::Last` and only the last
  chunk's logits are sampled (chunking does not consume RNG draws). Decode loop: `forward(&[tok]) -> Sampler::sample`
  until EOS, `--max-tokens` or a full cache; no device allocation. Output is streamed by decoding the full generated
  list and printing the new suffix (held back while it ends in U+FFFD). One untimed warm-up (prefill chunk + one
  decode step, then `reset`) removes cuBLAS lazy-init from the timers. Stats on stderr: prompt/generated tokens,
  prefill ms + tok/s, decode steps, ms + tok/s (each step `forward + sample`, timer read after `gpu.synchronize()`),
  stop reason; `--json` prints them as one JSON line. No `unwrap`/`expect`; errors are `Box<dyn Error>` (no anyhow).
- `engine/src/model/llama.rs` (outside `files`): `Llama::max_seq_limit(head_dim)` exposes the attention kernel's
  existing kv-length bound so the CLI can clamp `max_seq` instead of duplicating the shared-memory constant; the
  check in `Llama::new` now uses it (same inequality).
- `engine/tests/cli.rs` + `[[test]] name = "cli" required-features = ["gpu-tests"]` in `engine/Cargo.toml`
  (outside `files`, required to test the binary): writes a seeded synthetic BF16 checkpoint, `config.json`
  (bos 0, eos [1]) and a WordLevel tokenizer built with the `tokenizers` crate (with and without a `<s> $A`
  post-processor) under `CARGO_TARGET_TMPDIR`, then runs `CARGO_BIN_EXE_kvasir`. 6 tests: greedy output identical
  across two runs + exact JSON stats; sampled output identical for the same seed, identical across prefill chunk
  sizes, different for another seed; BOS added exactly once with and without the post-processor + chunked prefill;
  EOS / max-tokens / context-full stop reasons; human stats line; missing dir / missing config.json errors.
- Bookkeeping: `.agent/backlog.yaml` (S1-05 done), DESIGN.md §1, §2 ("Generation"), §7, CHANGELOG.md, README.md
  (usage snippet, status row).
