## changes
- engine/src/model/workspace.rs: `Workspace` owns `attn_scratch` (`attention_scratch_len(n_q, head_dim)` FP32,
  zeroed at allocation); `WorkspaceDims` gains `n_q`, `head_dim`, `attn_scratch_shape()`, counted in
  `device_bytes()` (unit tests extended). Chosen over `KvCache` because it is per-call working memory sized by `n_q`
  (a model property, not cache state); `KvCache` keeps only sequence state.
- engine/src/kv/mod.rs: `KvCache::attention` takes `scratch` and forwards it; attention is still called only there.
- engine/src/model/llama.rs: `ATTENTION_SMEM_BYTES` cap removed; `Llama::new` calls
  `kernels::check_attention_dims` (head_dim 64/128, group 1/2/4/8, Shape error otherwise); `max_seq_limit(head_dim)`
  kept with the same signature for S1-05's CLI, now `i32::MAX` (kernel `max_seq` is i32, offsets 64-bit);
  `max_position_embeddings` still enforced by `KvCache::from_config`.
- engine/src/gpu/kernels.rs (outside the listed files; it is where the contract lives): `check_attention_dims` (pub,
  shared by the wrapper and `Llama::new`) and alignment checks in `Gpu::attention`: qkv/kc/vc 16 B, out/scratch 4 B
  (half2 stores / f32), returning `KvasirError::Shape` before launch.
- engine/tests/kv.rs: pass scratch; new `misaligned_views_are_errors` (qkv offset by 1 and 4 halves, out by 1 → Shape
  error; 16-byte-aligned offset view succeeds).
- engine/tests/forward.rs: model moved to hidden 256, 4/2 heads of 64 (head_dim 16 is unsupported); embedding range
  ±1 → ±0.5 so logit rms stays ≈ 5, which is what TOL = 5e-2 (≈ 1% of rms) was calibrated against — with ±1 the
  logit rms doubled to 11.9 and errors scaled with it (worst of 30 = 4.8e-2). **Tolerances unchanged.**
  Re-measured over 30 random models (temporary sweep, not committed): worst vs FP16-emulated 2.67e-2, vs exact
  2.74e-2, decode-vs-prefill 2.51e-2 (were 2.14/2.40/1.99e-2 at head_dim 16; margin to TOL 1.8× instead of 2×),
  head-only 1.1e-5; bug references ≥ 187×TOL away. `rejects_bad_limits` additionally asserts that unsupported
  head shapes are rejected. Documented in DESIGN §6.
- engine/tests/workspace.rs (outside listed files): allocation-size test includes `attn_scratch` and checks it is zero.
- engine/tests/cli.rs (S1-05's file, in the merge commit): model to hidden 128, 2/1 heads of 64, embedding ±0.7 (same
  logit-scale reasoning; with ±1 two seeds sampled the same 96 tokens at temperature 1.5). No tolerance involved.
- engine/benches/forward.rs + [[bench]] in engine/Cargo.toml: synthetic full-size Llama 3.2 1B (seeded host pools
  tiled onto the device, 0.2 s), prefill 128, decode ctx 128/512/2048 (wall + device), logits D2H, host argmax;
  JSON + markdown table; compares with bench/forward-baseline.json (> 10% on any gated median fails).
- Makefile: `bench` = `bench-kernels` + `bench-forward`; `bench-baseline` rewrites both baselines. One gate because
  both are regressions a change must not introduce and the forward bench adds only ~7 s.
- bench/forward-baseline.json: new.
- DESIGN.md §1 (tree, scratch ownership), §2 (workspace buffer, forward-pass limits/alignment), §3 (scratch owner),
  §6 (test model), §7 (status row), §8 (forward bench, breakdown, bottlenecks); CHANGELOG; backlog I-01 (done).
