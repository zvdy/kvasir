## changes
- engine/kernels/gemv.cu (new): FP16 GEMV `y = W[out, in]·x`, FP32 accumulate. 2 rows per warp (gate/up pair for
  SwiGLU), 4 warps per block, lane l reads 16-byte chunks l, l+32, … via `ld.global.nc.L1::no_allocate` with 8 chunks per
  row in flight, x via `__ldg`, shuffle reduction. Epilogues: FP16, FP32 (LM head), residual add
  (`half(y + half(W·x))`), SwiGLU (`half(silu(half(g))·half(u))`). Optional RMSNorm prologue (raw hidden row + norm
  weight, `half(x·inv·w)` like the rmsnorm kernel; `inv` from the x chunks already in registers when in ≤ 2048).
- engine/src/gpu/gemm.rs: `gemv_f16 / gemv_f32 / gemv_add / gemv_silu_mul` + `Norm { w, eps }`; check `in % 8 == 0`
  (else `Shape`), lengths, 16-byte alignment of x / W / norm weight; i32 bounds. No allocation.
- engine/src/gpu/kernels.rs: load the four GEMV functions; `check_aligned` / `i32_of` shared with gemm.rs (the
  alignment message now carries its own prefix, attention callers pass `"attention: qkv"` etc.).
- engine/src/model/llama.rs: `T = 1` layers use the fused GEMVs (7 launches instead of 12: no rmsnorm, silu_mul,
  add); a single head row uses `gemv_f32` with the final norm fused (decode and prefill `Logits::Last`). `T > 1`
  unchanged (cuBLAS). `Llama::new` rejects hidden / q_dim / intermediate not divisible by 8.
- engine/tests/kernels.rs: 6 new GPU tests vs f64 CPU references: `gemv_f16` (3072×2048, 77×40, 9×2664),
  `gemv_f32` (128256×2048 LM head, 5×24), `gemv_add` (2048×2048, 2048×8192, 13×104), `gemv_silu_mul` (8192×2048,
  11×56), fused RMSNorm for all three norm-capable variants (2048 → 3072 / 8192, 296 → 21, 2664 → 9), shape errors
  (in not a multiple of 8, wrong lengths, misaligned x / W / norm weight). Tolerances are the existing GEMM ones:
  FP16 outputs `2e-3 rel + 1e-3 abs` (linear_f16), FP32 `1e-4 + 1e-4` (linear_f32). Max errors are single FP16
  output roundings (e.g. 1.9e-3 at |y| ≈ 2–4) and 1.4e-6 for FP32.
- engine/benches/kernels.rs: `gemv_*` entries (plain and as used with the fused norm); bench/*.json regenerated.
- docs/adr/0007-hand-written-decode-gemv.md (new), 0002 Status line "amended by 0007"; DESIGN.md §1/§2/§3/§4/§6/§7/§8;
  CHANGELOG; backlog P-01.

Tuning (all within ±1%, so the simplest config was kept): rows per warp 1/2/4, warps per block 2/4/8, unroll 4/8/16,
loads `.nc.L1::no_allocate` / `+L2::128B` / `+L2::256B` / `.cs` (plain `.nc` was 3–4% slower). A size sweep of plain
GEMVs (1024…16384 × 2048) fits `t = 2.1 µs + bytes / 470.6 GB/s`: the kernel streams at 93% of spec, the rest is a
fixed per-launch cost.
